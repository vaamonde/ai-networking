📝 **Estudos e Tecnologias para IA (AI) em Redes de Computadores (Habilidades do Profissional de TI em 2026)**

1. **O que é e para que server o Git?** O git é um __`Sistema de Controle de Versão Distribuído`__ que permite aos desenvolvedores rastrear mudanças em arquivos e colaborar em projetos de software. Ele é amplamente utilizado para **Gerenciar o Código-Fonte de Projetos**, facilitando a colaboração entre equipes e o __`Controle de Versões`__.
  - Site: https://git-scm.com/
  - Documentação: https://git-scm.com/docs

2. **O que é e para que serve o Github?** O GitHub é uma __`Plataforma de Hospedagem de Código-Fonte`__ que utiliza o sistema de controle de versão **Git**. Ele permite que os desenvolvedores armazenem, compartilhem e colaborem em projetos de software. O GitHub oferece recursos como repositórios, pull requests, issues e __`Integração Contínua`__, facilitando a colaboração e o **Gerenciamento de Projetos de Software**.
  - Site: https://github.com/
  - Documentação: https://docs.github.com/pt
  - Alternativa: https://about.gitlab.com/

3. **O que é e para que serve o VSCode?** O Visual Studio Code (VSCode) é um __`Editor de Código-Fonte`__ leve e poderoso desenvolvido pela **Microsoft**. Ele suporta uma ampla variedade de linguagens de programação e oferece recursos como depuração, __`Controle de Versão Integrado`__, extensões e personalização. O VSCode é amplamente utilizado por desenvolvedores para escrever, depurar e gerenciar código-fonte de maneira eficiente.
  - Site: https://code.visualstudio.com/
  - Documentação: https://code.visualstudio.com/docs

4. **O que é e para que serve o DevOps?** DevOps é uma prática de desenvolvimento de software que combina o __`Desenvolvimento (Dev) e as Operações (Ops)`__ para melhorar a colaboração, a automação e a **Entrega Contínua de Software**. O objetivo do DevOps é acelerar o ciclo de desenvolvimento, melhorar a qualidade do software e facilitar a __`Implantação e Manutenção de Aplicativos em Produção`__.
  - Documentação: https://pt.wikipedia.org/wiki/DevOps

5. **O que é e para que serve o Engenharia de Prompt?** A engenharia de prompt é a __`Prática de Criar e Otimizar Prompts para Interagir com Modelos de Linguagem`__, como o GPT-3.5. Ela envolve a __`Formulação Cuidadosa de Perguntas ou Instruções`__ para obter respostas mais precisas e relevantes dos modelos de linguagem. A engenharia de prompt é utilizada para **Melhorar a Eficácia das Interações com Modelos de Linguagem**, garantindo que as respostas sejam __`Alinhadas com as Necessidades do Usuário`__.
  - Documentação: https://pt.wikipedia.org/wiki/Engenharia_de_prompts

6. **O que é e para que server o LLM?** LLM (Modelos de Linguagem de Grande Porte) são __`Modelos de Inteligência Artificial`__ que foram treinados em grandes volumes de texto para entender e gerar linguagem natural. Eles são capazes de realizar uma variedade de tarefas, como **Responder Perguntas, Gerar Texto, Traduzir Idiomas e Realizar Análises de Sentimento**. Os LLMs são utilizados em diversas aplicações, desde __`Assistentes Virtuais até Análise de Dados`__, e são uma parte fundamental da IA generativa.
  - Documentação: https://pt.wikipedia.org/wiki/Modelos_de_linguagem_de_grande_porte

7. **O que é e para que serve o MCP (IA)?** O MCP (Protocolo de Contexto de Modelo) é um __`Protocolo de Comunicação`__ que permite a integração de __`Modelos de Linguagem`__, como o GPT-3.5, com outras ferramentas e sistemas. Ele facilita a **Troca de Informações e a Execução de Tarefas entre Modelos de Linguagem e Aplicativos Externos**, permitindo uma maior flexibilidade e funcionalidade na utilização de IA em diversos contextos.
  - Documentação: https://pt.wikipedia.org/wiki/Model_Context_Protocol

8. **O que é e para que server o Agente de IA?** Um agente de IA é um __`Sistema de Inteligência Artificial`__ que pode realizar tarefas específicas de __`Forma Autônoma`__, tomando **Decisões** e executando ações com base em __`Dados e Algoritmos`__. Os agentes de IA são projetados para **Interagir com o Ambiente**, aprender com as experiências e adaptar seu comportamento para alcançar objetivos específicos. Eles são utilizados em uma variedade de aplicações, desde __`Assistentes Virtuais até Sistemas de Automação Industrial`__.
  - Documentação: https://pt.wikipedia.org/wiki/Agente_de_IA

9. **O que é e para que serve o N8N?** O n8n é uma __`Ferramenta de Automação de Fluxo de Trabalho`__ de código aberto que permite aos usuários criar e **Automatizar Processos** sem a necessidade de codificação complexa. Ele oferece uma interface visual para criar fluxos de trabalho, integrando-se com uma ampla variedade de serviços e APIs. O n8n é utilizado para __`Automatizar Tarefas Repetitivas`__, integrar sistemas e criar **Fluxos de Trabalho Personalizados**.
  - Site: https://n8n.io/
  - Documentação: https://docs.n8n.io/

10. **O que é e para que serve o CI/CD?** CI/CD (Integração Contínua/Entrega Contínua) é uma prática de desenvolvimento de software que envolve a __`Automação do Processo de Integração e Entrega de Código`__. A Integração Contínua (CI) refere-se à prática de **Integrar Código Regularmente em um Repositório Compartilhado**, onde ele é automaticamente testado para detectar erros. A Entrega Contínua (CD) refere-se à prática de __`Automatizar a Entrega do Código para Ambientes de Produção`__, garantindo que as mudanças sejam implementadas de forma **Rápida e Confiável**.
  - Documentação: https://pt.wikipedia.org/wiki/CI/CD

11. **O que é e para que server o AIOps?** AIOps (Inteligência Artificial para Operações de TI) é uma abordagem que utiliza __`Inteligência Artificial e Aprendizado de Máquina`__ para melhorar as **Operações de TI**. O AIOps é projetado para __`Analisar Grandes Volumes de Dados de Operações`__, identificar padrões, detectar anomalias e automatizar tarefas para melhorar a **Eficiência e a Eficácia das Operações de TI**.
  - Documentação: https://pt.wikipedia.org/wiki/AIOps

12. **O que é e para que server o SRE?** SRE (Site Reliability Engineering) é uma disciplina de engenharia de software que se concentra em __`Garantir a Confiabilidade e a Disponibilidade de Sistemas`__. Os engenheiros de SRE aplicam princípios de engenharia para resolver problemas operacionais, automatizar tarefas e melhorar a **Resiliência e a Escalabilidade de Sistemas**. O SRE é utilizado para **Gerenciar e Operar Serviços em Produção**, garantindo que eles sejam confiáveis e atendam às necessidades dos usuários.
  - Documentação: https://pt.wikipedia.org/wiki/Site_Reliability_Engineering

1. Demonstração do Agente do Claude no VSCode executando o prompt no servidor Ubuntu Server

```md
[Persona]
Você é um SysAdmin DevOps Sênior de Infraestrutura GNU/Linux, especializado em auditoria e 
documentação de servidores Ubuntu Server (qualquer versão) rodando Containers Docker.

[Contexto]
A organização precisa padronizar a documentação técnica de seus servidores GNU/Linux que estão
rodando os Containers via Docker-CE para facilitar auditorias, troubleshooting (análise de 
problemas) e gestão de ativos (inventário).

[Escopo]
Coletar e documentar informações do servidor GNU/Linux Ubuntu Server rodando o Docker-CE nas
seguintes categorias:

- Versão do Docker
- Serviço do Docker
- Imagens
- Containers
- Volumes
- Redes

[Procedimento]
Utilizar comandos nativos do GNU/Linux Ubuntu Server (versão 24.04 LTS), não utilizar o comando 
sudo, usar comandos básicos do Docker-CE como por exemplo:

- hostnamectl
- docker info
- docker images
- docker volume ls
- docker network ls

[Critérios de Análise]
- Identificar imagens instaladas, versão, data, etc
- Identificar containers criados, data de criação, em execução ou não
- Identificar containers iniciados, parados ou com falhas
- Identificar containers de serviços específicos
- Identificar containers de gerenciamento utilizado pelo Docker

[Tarefa]
1. Levantar todas as informações técnicas do servidor Ubuntu Server e do Docker-CE
2. Organizar os dados em formato estruturado para facilitar a leitura
3. Identificar possíveis falhas de segurança com base nas informações coletadas
4. Sugerir melhorias de desempenho e segurança para o Ubuntu Server e o Docker-CE

[Formato]
Saída obrigatória no padrão de tabela Markdown com ícones para facilitar a leitura e entendimento

| Categoria | Descrição | Configuração |
|-----------|-----------|--------------|

Exemplo:
| Categoria | Descrição     | Configuração   |
|-----------|---------------|----------------|
| Rede      | Endereço IPv4 | 10.24.82.200/24|

[Camada de Tradução]
1. Após cada seção técnica, incluir uma explicação simplificada para público não técnico.
2. Não traduzir termos técnicos como por Exemplo: Snapshots - Fotografia do Momento

Exemplo:
"Este servidor possui 4GB de memória RAM, o que pode limitar o desempenho em horários de pico."
"Este servidor está sendo utilizado para Web Server, cuidado em períodos sazonais."

[Severidade]
Classificar problemas encontrados como:
- Baixo
- Médio
- Alto

[Interação]
Não fazer perguntas ao usuário. Trabalhar apenas com os dados disponíveis.

[Público]
Gerentes de TI e Equipe Administrativa, com baixo conhecimento técnico em GNU/Linux e Docker-CE

[Restrições]
Não utilizar ferramentas de terceiros ou softwares que precisam ser instalados no servidor para
executar essa tarefa

[Saída]
Salvar o resultado no diretório com o nome: ubuntu-docker-audit.md
```
